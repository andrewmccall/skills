# Find the itch

Discover what is genuinely interesting before drafting. Do not write the whole piece unless the user explicitly asks.

Load `VOICE.md` and `STYLE.md` from the user-named profile or the first available profile at `.writing/`, `.writing-profile/`, `~/.writing/` or `~/.codex/writing-profile/`. Continue without a profile when none exists.

## Work conversationally

State the obvious version of the piece briefly, then look past it. Explore:

- disagreement with the conventional explanation;
- contradiction or useful tension;
- a supposedly new problem that resembles an old one;
- hidden complexity or missing ownership;
- a gap between theory and practice;
- the easy problem receiving attention while the hard problem is ignored;
- a decision the available facts should change.

Ask one or two questions at a time. Push for a concrete experience, system, decision or observation. Do not manufacture controversy the user does not believe.

Generate a small set of genuinely different candidate claims. For each, explain why it is interesting, what would need to be demonstrated and who might reasonably disagree. For non-argumentative documents, replace disagreement with the decision enabled and the trade-off exposed.

Use discomfort as a detector, not a goal: what is the strongest formulation the user actually believes but might hesitate to publish?

## Finish

Return a concise synthesis covering the itch, strongest claim or decision, strongest counterargument or trade-off, concrete experience or evidence, what still needs proof, and the question the piece must answer.
