# Learn from feedback

Make personalisation visible, evidence-based and reversible.

Locate the user-named profile or the first profile at `.writing/`, `.writing-profile/`, `~/.writing/` or `~/.codex/writing-profile/`. Read its guides, relevant examples and recent decisions. If no writable profile exists, propose where to create one rather than modifying a skill.

## Find durable evidence

Compare the source, suggestions, user feedback and final text. Look for repeated preferences, not isolated choices caused by one audience or format.

Possible destinations:

- `VOICE.md` for sound, rhythm, diction and identity;
- `STYLE.md` for argument, evidence, structure and purpose;
- `ELEMENTS.md` for sentence-level editing principles;
- `examples/` for approved passages that demonstrate an existing principle;
- `decisions/` for the provenance of an accepted, rejected or superseded rule.

Do not infer a global preference from silence, one accepted edit or one format constraint. Do not encode confidential content in a profile example without explicit approval.

## Propose before writing

Present at most a few high-confidence proposals. For each include the observation, evidence, exact change, destination, expected future effect and risk of overgeneralisation.

Ask for approval. Do not edit the profile in the same step unless the user already explicitly authorised applying the proposed changes.

When approved, make the smallest coherent edit and add a dated decision when the reason would be useful later. Preserve rejected proposals in a decision only when the user wants that history retained.

Never silently rewrite generic skill logic to encode one person's taste.
